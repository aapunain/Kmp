# AGENTS.md

Instructions for any AI coding agent working in this repository. This is the
canonical file; `CLAUDE.md` and `GEMINI.md` are symlinks to it. Keep it under
~200 lines so it always fits in context — detail belongs in `docs/`, linked below.

## What this project is

Kotlin Multiplatform, clean architecture, targeting Android, iOS, desktop (JVM),
web (JS + Wasm) and a Ktor server. Kotlin 2.4.20, Gradle 9.5.1, AGP 9.1.1.

```
app/          entry points: androidApp, desktopApp, iosApp, webApp, shared
contract/     HTTP models + endpoint paths, shared with the server
core/         domain, data, network, concurrency   (a directory, NOT a module)
presentation/ Compose UI + ViewModels
server/       Ktor backend
build-logic/  convention plugins and the executable architecture rules
docs/         architecture, conventions, testing, pitfalls, ADRs
```

## The one command that matters

```bash
./gradlew verify
```

Runs formatting, static analysis, architecture rules, coverage, and tests on
**all five platforms** plus every app entry point. Takes 6–7 minutes cold.

```bash
./gradlew qualityCheck   # seconds: format + detekt + architecture + conventions
./gradlew spotlessApply  # fix formatting automatically
```

`./gradlew build` and a single `jvmTest` are **not** sufficient evidence. Two real
bugs in this repo were invisible from JVM compilation alone — see
[docs/KMP_PITFALLS.md](KMP_PITFALLS.md).

## Definition of done

Do not report a task complete until all of these hold.

1. `./gradlew verify` passes, and you **paste the actual result** — task outcome and
   test counts. "All tests pass" is not evidence; "verify green, 19 tests × 5
   targets, 0 failures" is.
2. You state explicitly **what you could not verify** (iOS device behaviour, real
   backend calls, anything needing a simulator or hardware).
3. If you changed architecture, you updated `moduleGraph`, ran
   `./gradlew architectureDocs`, and added an ADR.
4. Temporary files and scratch scripts are deleted.
5. The diff contains only what the task asked for. No drive-by refactors.

If a gate fails, **fix the cause**. Do not disable a rule, add a suppression, or
widen an exclusion to get green. If a rule is genuinely wrong, say so and explain
why, but do not silently weaken it.

## Non-negotiable rules

1. **Dependency direction is enforced.** `moduleGraph` in
   `build-logic/src/main/kotlin/kmp.architecture.gradle.kts` is the source of
   truth. Adding a module dependency that isn't in it fails the build.
2. **`:core:domain` depends on nothing.** Not coroutines, not Koin. Ever.
3. **No module named `core`, `common`, `util` or `shared`.** Name modules for
   responsibility, not position. See [ADR-0003](adr/0003-no-catch-all-modules.md).
4. **Two result types, one translator.** `ApiResult`/`ApiError` live in
   `:core:network`; `AppResult`/`AppError` live in `:core:domain`. `:core:data` is
   the only place both are visible. No HTTP status code may appear above `:core:data`.
5. **Never reference `Dispatchers.IO`.** It does not exist on JS/Wasm and is
   `internal` on Native. Inject `DispatcherProvider`. Enforced by `conventionsCheck`.
6. **Implementations are `internal`; interfaces are public.** `explicitApi()` is on,
   so every public declaration needs an explicit `public` and return type.
7. **Versions only in `gradle/libs.versions.toml`.** Never inline a version string.
   Enforced by `conventionsCheck`.
8. **Modules with `internal` implementations publish their own Koin module.**
   `:core:domain` is wired from the composition root instead, because its use cases
   are public. Ownership of wiring follows visibility.
9. **Hand-written fakes, never mocking libraries.** MockK and Mockito are JVM-only
   and will not compile for iOS, JS or Wasm.
10. **`UiState` holds display-ready types**, not domain models. One immutable state
    class, a sealed `Intent`, a single `onIntent` entry point.
11. **Adding a module** requires: a one-sentence charter, two or more consumers, an
    entry in `settings.gradle.kts`, `moduleGraph` and `moduleCharters`, plus an ADR.
12. **Record an ADR for any structural or convention decision.** Append-only; never
    edit an existing ADR, supersede it.

## Do not touch

- `**/build/**`, `**/.gradle/**`, `**/.kotlin/**` — generated
- The block between `ARCHITECTURE-GRAPH:START/END` in `docs/ARCHITECTURE.md` —
  generated by `./gradlew architectureDocs`
- `kotlin-js-store/yarn.lock` — regenerate via Gradle, never hand-edit
- `gradle/wrapper/**` — changing the Gradle version is its own task with an ADR
- `app/iosApp/**/*.xcodeproj/**` — Xcode-managed, merge-hostile
- `local.properties` — machine-specific, not committed

## Working style

- Read before writing. Never propose changes to code you have not read.
- Prefer the smallest change that solves the problem. A bug fix does not need the
  surrounding code cleaned up.
- If the same approach fails twice, stop and diagnose the root cause instead of
  making incremental tweaks.
- State uncertainty plainly. "I could not verify X" is more useful than a confident
  guess.
- Match existing style and libraries. Do not introduce a new dependency without
  saying why in the summary.

## Common commands

```bash
# run the apps
./gradlew :app:desktopApp:run
./gradlew :app:androidApp:assembleDebug
./gradlew :app:webApp:wasmJsBrowserDevelopmentRun
./gradlew :server:run                      # iOS: open app/iosApp in Xcode

# targeted tests
./gradlew :core:domain:jvmTest
./gradlew :app:shared:iosSimulatorArm64Test    # macOS only
./gradlew :presentation:wasmJsTest

# diagnostics
./gradlew koverLog                         # coverage per module
./gradlew architectureDocs                 # regenerate the module graph docs
```
